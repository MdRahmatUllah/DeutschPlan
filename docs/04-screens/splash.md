# S1 · Splash

**Purpose.** Cover database opening and first-run content copy; route to onboarding or Today.

**Prototype.** `Splash-android.html` — app mark, wordmark, caption "Preparing your course · first start only". The mark and the wordmark are now the brand kit's stacked lockup (`docs/sogda-brand-kit/svg/lockup-stacked-tiles-light.svg`, #602): the tiles, an "a" on Paper behind an "Ä" on Sun (the kit's own letter outlines), over "Sogda" in Inter ExtraBold, tracked −2 %. The artboard's "D" speech bubble is gone.

**Reached from.** App icon, reminder notification, widget, deep link. **Leads to.** S2 (no enrollment) · T1 · or the deep-link target.

**Layout.** Native launch screen (Android 12 SplashScreen API, iOS LaunchScreen) shows the mark; Flutter's first frame is the same composition so there is no visible hand-off. On Android 12+ the system splash's exit reveal is removed at once, not animated (`MainActivity`, #854): a reveal cut short under load is the likeliest cause of an app-wide ~12 % dim SQA saw three times. A thin Lagoon progress line under the mark appears only if bootstrap exceeds 600 ms.
- **The mark (#602).** Drawn in Flutter (`SgMark`, `core/components/sg_mark.dart`), no picture and no new dependency: the kit's 108 grid, its letters the kit's own outlines (the SVG's path data, parsed once), not a font, so the launcher, the native splash and S1 share one letterform; framed 1.32× in a 218 dp square (288 / 1.32), which puts the tiles at Android 12's own scale (its splash icon is the grid on a 288 dp canvas, masked to the inner 192 dp circle). The square's centre is the screen's, where Android 12 and the pre-12 window (`splash_mark.xml`, the same art cropped tight) draw it, so the hand-off moves nothing (FR-S1-05); the wordmark and the caption appear under it. The scaffold keeps the body above the navigation bar, so the screen gives the bar's height back at the top. That needs edge to edge, which Android applies from 10 (API 29): on 8 and 9 (API 26–28) the app is laid out above the bar and the mark lands about 24 dp above where the window drew it. Under the mark: the wordmark at 84/200 of the square, its cap height 18.7/200 below it, as the kit's lockup sets them; then 40 dp and the progress line's slot. The column carries as much empty space above the mark, which centres it, and which the iOS launch image, rendered from the column, carries too. An invisible twin of the caption (opacity 0, so no reader hears it) sits over the lockup and balances the caption under it; between them the lockup is scaled down, never cropped, on a screen too short for it (a 360 × 640 phone at 200 % text, a tablet on its side), 16 dp clear of the caption, and as much above, so the centre stays the screen's (#744). The progress line is its own layer: its animation repaints nothing else.
- **Colours.** The field is `primary`: Lagoon, and in dark the lifted Lagoon, as `colors.xml` paints the native window. The tiles and the wordmark are the kit's own colours in every mode (`SgBrand`), Ink on Lagoon: the kit never recolours them. The caption and the progress line are `onPrimary` (Ink, the same as the wordmark), the line over the light track (Ink at 47 %), in both modes: the dark page's light ink was about 1.4:1 on the lifted Lagoon, and `onPrimary` is 11.8:1 there (#605). Under glass they are the page's tokens. Under glass the aurora is the ground, so the mark takes its Lagoon square (the kit's rule for any other ground) and the wordmark the page's ink; no panel.
- **Text size.** The mark and the wordmark are the logo: they keep their size at any text size. The caption scales.
- **The error state** (FR-S1-03) draws the same lockup at 60 %, so the message and both actions reach above the fold on a 360 × 640 phone.

**Functional requirements**
- FR-S1-01 Bootstrap MUST: open user.db (create schema if absent), copy content.db when `content_version` differs, attach it, check that its FTS5 trigram index answers (ADR 14, #596), load settings, resolve theme.
- FR-S1-02 Warm start to Today MUST be < 500 ms; first run (content copy) SHOULD be < 2 s.
- FR-S1-03 On bootstrap failure show a full-screen error with *Retry* and *Export progress* — never a blank screen. A *Retry* that works opens the app as a first start does: its own provider container with bootstrap's overrides, and the same light/dark hook, reminders, widget, downloads and voice (#643). Retry and *Export progress* never run together, each disabled while the other works; a Retry that throws stays live, the database closed before a content retry deletes the course file; an export that fails says so (#652). When user.db itself won't open (a corrupt file, or one a newer build wrote), its connection is closed and *Share your data file* stands where *Export progress* does and shares `user.sqlite` with its `-wal`; a file past this build's schema says to update the app rather than to retry (#619). A share that fails says the file wasn't shared, not that an export didn't finish (#843). A course copy that failed for space (ENOSPC) says so: "There isn't room on this phone for the course. Free about 10 MB, then tap Retry." (`courseInstallMegabytes`, the course and a margin); any other content failure says Sogda could not install the course (#803). The error is in the learner's app language when user.db opened before the failure, as the splash was (`ui_language`'s default, English, on a first run), a *Retry* that got further included; when user.db didn't open, in the phone's (#720).
- FR-S1-04 Deep links and notification taps MUST be honoured after bootstrap.
- FR-S1-05 The native launch screen and Flutter's first frame MUST show the same mark at the same place (#602).

**Business rules.** BR-CONTENT-01/02 (uid stability during content copy).

**States.** first run · normal · updating content · error. The caption is "Preparing your course · first start only" (`splashPreparing`) from the first frame, on a first start and a warm one alike. When an app update finds a newer bundled course and starts copying it in, it changes to "Updating the course…" (`splashUpdating`) for the rest of the wait; never on a first start, whose copy the first caption names (the owner's decision on #686 ST-9: bootstrap's `onCourseUpdate`).

**Motion.** Mark shrinks toward Today's ring position while Today fades up 8 px (standard).

**Data.** `bootstrap.dart` → `AppDatabase.open()`, `ContentUpdater.check()`, `SettingsRepository.load()`.

**Developer notes.** Keep all I/O in `bootstrap()`, before the app's first frame (S1 shows meanwhile); use `FlutterNativeSplash`-style preserve/remove only if the platform splash flickers. Probe the bundled asset's version without loading the whole course (about 7.5 MB at 1.1.0) into memory twice (write to a temp file once).

**Tests.** Widget: error state shows Retry; unit: content version diff triggers copy and update-card row.
