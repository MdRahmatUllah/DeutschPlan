# Adding or changing content

1. Edit the workbook in `data/` (or add a new one and register it in `content/manifest.yaml`, listing under its entry's `without:` any column the maps read that it doesn't have: "Adding a workbook" in `docs/02-data/content-pipeline.md`). `data/` is git-ignored: the workbooks live only in the checkout where content is edited. Keep header names; add words to *All Words* with a `Level`; add grammar rows to *Grammar*. A tool never writes a workbook (openpyxl drops their charts, #545): a fix made in the repo goes into `content/corrections.yaml`, keyed by the row's uid, with a `why` ("Corrections" in `docs/02-data/content-pipeline.md`).
2. Avoid cells starting with `=`, `-`, `+`, `@` (prefix with text); keep one example per line.
3. `make content` — the tool prints counts per step, uid collisions, what changed since the committed asset (added/removed/changed) and verification results.
4. Changing `german`, `pos`, `english` or `level` of an existing entry changes its uid. The build links the old uid to the new one when it is the same word (same level, German and part of speech; or same German, part of speech and English — PIPE-09), prints each `uid link`, and the app moves the learner's progress along it. Check the links are right: a wrong one is refused (`refuse: true`), and a missing one pinned (`to: "<uid>"`), under `links:` in `content/corrections.yaml`, with a `why` (#807). Renaming or re-levelling a grammar topic changes its uid too: a re-levelled one is linked by its title, and a renamed one stops the build until it is pinned (#808). A word that is gone with nothing to link it to **stops the build**: its learners would lose their progress on it. Restore it, or rerun with `--allow-removed` and say so in the release notes.
   Each level keeps the step boundary week the committed course has (PIPE-02, #923), so adding or dropping rows never moves a level's other words between steps under learners. The build says when the level's middle has moved away from it (`boundary kept: …`); `--move-boundaries` moves it, and the words with it: say so in the release notes.
   A meaning language (Russian, Polish …) is its own columns, `Meaning (X)`, `Pronunciation (X)`, `Examples (X)` and the Grammar's `Topic (X)` … `Watch out (X)`, in every workbook. The build prints each language's counts and ships it only when it is 100 % complete; `--allow-partial <code>` builds a partial one for testing (#1080, "Adding a meaning language" in `docs/02-data/content-pipeline.md`).
5. Keep `data/denylist.txt` (personal details that must never ship, one per line) in the checkout: the verify step fails on any of its terms (#628), and says so when the file is missing.
6. Add interference tips in `content/interference_tips.csv` when a new false friend or trap enters, in the `tip_<code>` column of each language whose speakers it is for.
7. Run `flutter test test/db/` (the content database tests) and commit `app/assets/db/content.db` and `content_manifest.json` together.
